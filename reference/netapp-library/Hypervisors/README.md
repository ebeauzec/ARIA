- **ONTAP tools for VMware vSphere 10.5 — confirmed via direct fetch 2026-08-08** ([What's new in ONTAP tools for VMware vSphere 10.5](https://docs.netapp.com/us-en/ontap-tools-vmware-vsphere-105/release-notes/whats-new.html)): this resolves the platform-support claim flagged 2026-07-31 as not yet direct-fetch-verified. - **New: ONTAP tools for VMware vSphere 10.6 now current, superseding 10.5 — confirmed via direct fetch 2026-08-08** ([What's new in ONTAP tools for VMware vSphere 10.6](https://docs.netapp.com/us-en/ontap-tools-vmware-vsphere-10/release-notes/whats-new.html), dated 07/20/2026 — the unversioned `ontap-tools-vmware-vsphere-10` URL now resolves to 10.6). Headline changes: **granular datastore-level protection** (protect selected datastores rather than a whole host cluster, for both ONTAP and ASA r2, with Automated Failover Duplex/async policies, iSCSI/FC VMFS, hierarchical consistency groups and fan-out); **audit logging** (all non-GET REST calls, discovery/AutoSupport/cleanup jobs, tamper-evident log archives, syslog forwarding); **nconnect support for NFS datastores** (multiple parallel TCP connections, NFSv3 at provisioning and NFSv4.1 with vCenter 8.0U3+); a new smaller **XS deployment profile** as the default (alongside S/M/L); and a migration from `ntpd` to `chronyd` for time sync (auto-migrated on upgrade). If scoping a new ONTAP tools deployment today, default to 10.6 rather than 10.5. **Re-confirmed 2026-09-07 via direct fetch**: the unversioned `ontap-tools-vmware-vsphere-10` what's-new page still tops out at 10.6 (page contributor-dated 07/20/2026, no 10.7 in the version selector) — 10.6 remains current. **Re-confirmed again 2026-09-14 via direct fetch**: page content and contributor date (07/20/2026) unchanged; version selector still lists only 10.6 down to 10.0 — no 10.7 found this pass either.
- Cross-reference: for cloud-target DR of VMware workloads rather than a second on-prem site, see [NetApp Disaster Recovery (NetApp Console/BlueXP)](../Cloud-BlueXP/README.md#advanced-cloud-integrations) — SRM/SRA is the on-prem-to-on-prem (or on-prem-to-same-vCenter-domain) path; NetApp Disaster Recovery is the purpose-built path to a cloud SDDC.
- **Risk note**: a Live Site Recovery / SRM-orchestrated failover is, by definition, a **disruptive-but-data-safe** operation under the [Operating Protocol](../OPERATING-PROTOCOL.md) — it should only be invoked after confirming the SnapMirror relationship backing the protected datastores is healthy and current (stale replication turns a "safe" failover into a data-loss event bounded by the last successful update, not zero). Always run a non-disruptive **test failover** in an isolated network bubble before a real failover if the protection plan supports it.

### VMware Cloud Foundation (VCF) 9 with ONTAP
**New subsection, added 2026-07-11** — VCF 9 is Broadcom/VMware's current private-cloud architecture (compute + network + storage + management, the successor framing to standalone vSphere for greenfield private-cloud designs) and was not previously covered separately from generic vSphere.
- [Simplify hybrid cloud experience with VMware Cloud Foundation and ONTAP](https://docs.netapp.com/us-en/netapp-solutions-virtualization/vmware/vmw-vcf-overview.html) · [Design options with VCF and ONTAP](https://docs.netapp.com/us-en/netapp-solutions-virtualization/vmware/vmw-vcf-design.html) · [Set up private cloud environments with VCF and ONTAP](https://docs.netapp.com/us-en/netapp-solutions-virtualization/vmware/vmw-vcf-deployment.html) · [Configure iSCSI storage in a VCF management domain using ONTAP tools](https://docs.netapp.com/us-en/netapp-solutions-virtualization/vmware/vmw-vcf-mgmt-supplemental-iscsi-storage.html) · [VMFS on FC as supplemental storage for VI Workload/Management Domains](https://docs.netapp.com/us-en/netapp-solutions-virtualization/vmware/vmw-vcf-viwld-mgmt-supp-fc.html).
- [VCF 9 storage options (NetApp community deep-dive)](https://community.netapp.com/t5/Tech-ONTAP-Blogs/VCF-9-Storage-options/ba-p/462854) · [Private Clouds Made Easy with VMware Cloud Foundation 9 and ONTAP](https://community.netapp.com/t5/Tech-ONTAP-Blogs/Private-Clouds-Made-Easy-with-VMware-Cloud-Foundation-9-and-ONTAP/ba-p/457505) · [VMware Cloud Foundation deployment options with NetApp](https://community.netapp.com/t5/Tech-ONTAP-Blogs/VMware-Cloud-Foundation-deployment-options-with-NetApp/ba-p/451876)
- Architecture: ONTAP supports both **standard** and **consolidated** VCF architectures, providing unified block (VMFS on FC/iSCSI) and file (NFS) storage for the same VCF Fleet from a single platform. **One instance of ONTAP Tools for VMware vSphere (OTV) can manage all VCF Fleets in the same datacenter**; SnapCenter Plug-in for VMware vSphere requires one appliance per VCF Domain (not shared across domains like OTV).
- **SnapMirror active sync integration**: the current release of ONTAP Tools for VMware supports SnapMirror active sync, providing symmetric active-active data replication for VCF workloads — datastores created by OTV, including those protected by SnapMirror active sync, can be consumed by vSphere Supervisor (Kubernetes-on-vSphere), extending the same protection model into the Supervisor-managed workload layer.
- Deployment flexibility: ONTAP supports VCF both on-premises and in the cloud (AWS, GCP, Azure) — relevant when a customer's VCF strategy spans on-prem private cloud and a hyperscaler-hosted VCF deployment and wants one storage operating model across both.
- **Design note**: don't default to treating VCF as "just vSphere with extra steps" — VCF's Fleet/Domain management model changes the OTV-to-domain and SnapCenter-appliance-to-domain cardinality versus a standalone vCenter design; confirm the target VCF topology (single Fleet vs. multi-Fleet, management vs. VI Workload Domain counts) before sizing the ONTAP tooling footprint.

## Proxmox Virtual Environment (VE)
**New section, added 2026-07-18** — confirmed via direct fetch of a full new NetApp documentation tree at [docs.netapp.com/us-en/netapp-solutions-virtualization/proxmox/](https://docs.netapp.com/us-en/netapp-solutions-virtualization/proxmox/), not previously indexed in this library. This is a genuinely new platform addition, not a rename/rebrand of existing coverage.
- [NetApp Proxmox virtualization solutions hub](https://docs.netapp.com/us-en/netapp-solutions-virtualization/proxmox/) · [Learn about the Proxmox Virtual Environment](https://docs.netapp.com/us-en/netapp-solutions-virtualization/proxmox/proxmox-overview.html) (direct-fetched, dated 01/09/2026) · [Learn about ONTAP storage architecture for Proxmox VE](https://docs.netapp.com/us-en/netapp-solutions-virtualization/proxmox/proxmox-ontap-architecture.html) · [Learn about storage protocols for Proxmox VE with ONTAP](https://docs.netapp.com/us-en/netapp-solutions-virtualization/proxmox/proxmox-ontap.html) · [Supported storage types for Proxmox VE](https://docs.netapp.com/us-en/netapp-solutions-virtualization/proxmox/proxmox-storage-types.html) · [Configure NFS storage for Proxmox VE](https://docs.netapp.com/us-en/netapp-solutions-virtualization/proxmox/proxmox-ontap-nfs.html) · [Configure LVM with iSCSI for Proxmox VE](https://docs.netapp.com/us-en/netapp-solutions-virtualization/proxmox/proxmox-ontap-iscsi.html)
- **What it is**: Proxmox VE is an open-source, Debian-based Type-1 hypervisor supporting both full VM virtualization (KVM/QEMU) and Linux Containers (LXC) on the same host, with a Corosync-based cluster manager, RESTful API, and Proxmox Datacenter Manager for multi-cluster management. ONTAP provides both NAS (NFS, SMB) and SAN (FC, iSCSI, NVMe-oF) storage backends for Proxmox VE VM/container disk images.
- **Storage Manager for Proxmox (SMP)** — [configure and use SMP](https://docs.netapp.com/us-en/netapp-solutions-virtualization/proxmox/proxmox-smp.html) (direct-fetched, dated 04/07/2026). A standalone, Windows-hosted orchestration tool (downloaded from the NetApp Console Automation Hub, or installed as a Shift Toolkit add-on under Settings → Advanced → Storage Manager) that gives Proxmox admins direct, self-service ONTAP storage management: NFS/iSCSI datastore provisioning, crash-consistent and file-consistent (QEMU fsfreeze) VM backup via ONTAP Snapshot, VM/datastore restore, and rapid FlexClone-based VM cloning for dev/test. Prerequisites: PVE 9.x+ cluster, ONTAP AFF with NFS/iSCSI enabled at the SVM level. Backup replication (SnapMirror/SnapVault after backup) is present in the UI but **disabled in the current release** — note this to a customer evaluating SMP for a DR-replicated design today, not just local backup.
- **Proxmox Backup Server (PBS) with ONTAP** — [PBS architecture](https://docs.netapp.com/us-en/netapp-solutions-virtualization/proxmox/proxmox-pbs-architecture.html) · [deployment requirements/considerations](https://docs.netapp.com/us-en/netapp-solutions-virtualization/proxmox/proxmox-pbs-requirements.html). Separate from SMP — PBS is Proxmox's own incremental/dedup/compression/encryption backup product; NetApp's documentation covers deploying it against ONTAP storage with SnapMirror-based DR replication.
- **Migration in**: see [Migration — Shift Toolkit](../Migration/README.md#application-based-migration) for the ESXi-to-Proxmox-VE conversion path, added the same week as this section.
- **Design note**: this is new-to-market NetApp documentation (earliest dated page found this pass: 01/09/2026; the Shift Toolkit ESXi→Proxmox migration page is dated 07/02/2026) — treat as an emerging, not yet battle-tested integration for customer-facing commitments; confirm current PVE version compatibility (9.x+ required across all the pages checked) and SMP feature-completeness (e.g., the disabled replication toggle above) against the customer's specific requirements before scoping.

## Cross-hypervisor notes
- All four platforms converge on the same host-side building blocks documented in [Host-Integration-Cabling](../Host-Integration-Cabling/README.md): ALUA multipathing, Host Utilities Kits, and dedicated storage networking with jumbo frames. Proxmox VE (above) is a fifth, newly-documented platform following the same NFS/iSCSI/FC storage-network patterns.
