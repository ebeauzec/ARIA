- Architecture: Trident runs as one Controller Pod plus a Node Pod per worker node; CSI-compliant, supports NAS (NFS/SMB) and SAN (iSCSI, FC, NVMe/TCP) provisioning against ONTAP, Element/HCI, and cloud-native ONTAP (CVO/FSx for ONTAP).
- Multi-tenancy: dedicate an SVM per tenant/namespace grouping and set an SVM volume-count limit — prevents a single misconfigured StorageClass from exhausting the backend.
- Naming note: NetApp uses "Trident" and "Astra Trident" interchangeably in current docs; the product line also now includes "Trident Protect" as a distinct advanced-protection component — don't conflate it with Astra Control below, which is the multi-cluster/hybrid-cloud management plane.

### Advanced Astra Control workflows
- [Storage class migration with Astra Control (NetApp community deep-dive)](https://community.netapp.com/t5/Tech-ONTAP-Blogs/Storage-class-migration-with-Astra-Control/ba-p/447751) — migrate an app's PVs to a different StorageClass/backend without an application-level export/import.
- [Automating registry failover for DR with Astra Control post-restore hooks (NetApp community)](https://community.netapp.com/t5/Tech-ONTAP-Blogs/Automating-registry-failover-for-disaster-recovery-with-Astra-Control-post/ba-p/446272) — execution hooks are custom scripts run in conjunction with a data-protection operation (e.g., rewriting a container image registry URL as part of a post-restore hook when failing an app over to a different cluster/cloud).
- [Astra Control – Selective Restore (NetApp blog)](https://www.netapp.com/blog/astra-control-selective-restore/) — restore a subset of an application's resources/data rather than the entire app, useful for surgical recovery from partial corruption or accidental deletion.
- [DR of AKS workloads with Astra Control Service + Azure NetApp Files](https://bluexp.netapp.com/blog/astra-blg-disaster-recovery-of-aks-workloads-with-astra-control-service) — worked example of cross-region Kubernetes DR on Azure.
- [Data migration using Astra Control Center (RHHC self-managed solutions guide)](https://docs.netapp.com/us-en/netapp-solutions/rhhc/self-managed/data-migration.html)
- Execution hooks run at defined points (pre-snapshot, post-snapshot, pre-restore, post-restore) around a protection operation — use them for application quiescing (e.g., flush a database before snapshot) or environment-specific fixups (e.g., registry URL rewrite) rather than trying to solve those problems at the Trident/CSI layer, which has no application awareness.
- **Risk note**: a "restore" or "failover" operation in Astra Control overwrites or replaces the target application's running state — always confirm which cluster/namespace is the source of truth before executing, and use Selective Restore rather than a full-app restore when only a subset of data needs recovery, to avoid unnecessarily reverting healthy resources.
