  - **New platform, added 2026-08-08 — direct-fetch confirmed**: **AFX** (NetApp's disaggregated high-performance NAS/S3 platform, aimed at AI/ML workloads) uses a **separate documentation tree**, not the `ontap-systems/<platform>/` pattern above — [Cable the hardware for your AFX 1K storage system](https://docs.netapp.com/us-en/ontap-afx/install-setup/cable-hardware.html) (page dated 07/01/2026). Notable cabling specifics confirmed from the page: AFX 1K uses **4x100GbE breakout cables** for cluster/HA/storage connections (400GbE at the switch port, 100GbE at the controller/shelf port — e1a/e1b for HA, e7a/e7b for cluster, e10a/e11a and e10b/e11b for storage, all "a" to switch A / "b" to switch B); management ports use standard 1000BASE-T RJ-45; Cisco Nexus 9332D-GX2B and 9364D-GX2A switches specifically require the 4x100GbE breakout; and **mixed copper/optical breakout connections are unsupported on NVIDIA CX6-DX/CX7 100GbE NICs** (can cause link saturation after extended use — cite [KB CHW-3504](https://kb.netapp.com/on-prem/ontap/OHW/OHW-Issues/CHW-3504) if a customer asks why cable types can't be mixed).
- **Switch sizing for large AFX clusters — new, added 2026-09-02, direct-fetch confirmed**: [Hardware details](https://docs.netapp.com/us-en/ontap-technical-reports/afx/afx-hardware.html) (08/21/2026) publishes a port-math sizing table not previously indexed here — for a **32-node cluster** (now confirmed the current AFX node maximum, see [Platforms-Hardware](../Platforms-Hardware/README.md#afx--disaggregated-ontap-for-ai-scale-workloads)), AFX 1K fits on a Cisco Nexus 9364D-GX2A or 9808, while **AFX 2K at 32 nodes requires the Cisco Nexus 9808 specifically** (the 9332D-GX2B and 9364D-GX2A don't have enough usable 400GbE ports for AFX 2K's 3-ports-per-node-per-switch requirement at that scale). Below 32 nodes, smaller switches fit smaller clusters — e.g., a 9332D-GX2B supports up to 20 AFX 1K nodes + 5 shelves, or up to 8 AFX 2K nodes + 2–3 shelves. Confirm exact port counts against this page or Hardware Universe before finalizing a switch BOM for an AFX design.
- **AFX 2K cabling specifics now confirmed, 2026-08-17 direct-fetch** (previously flagged in this library as not independently checked): AFX 2K has its own dedicated install/cable workflow, distinct from AFX 1K — [Installation and setup workflow for AFX 2K](https://docs.netapp.com/us-en/ontap-afx/install-afx-2k/install-setup-workflow.html) (06/24/2026) → [Cable the hardware for your AFX 2K storage system](https://docs.netapp.com/us-en/ontap-afx/install-afx-2k/cable-hardware.html) (07/01/2026). Key differences from AFX 1K: AFX 2K controllers use **11 numbered I/O slots** (vs. AFX 1K's smaller port set) and cable at **400GbE directly** (not 4x100GbE breakout) for HA (e1a/e1b), cluster (e2a/e2b), host-network (e3a/e3b, e9a/e9b), and controller-to-switch storage (e10a/e8b — note e10b and e8a are unused for storage on AFX 2K); only the **shelf-to-switch** connections still use 4x100GbE breakout cabling (module A/B ports e1–e4 per side, same NX224 shelf pattern as AFX 1K). Management is the same 1000BASE-T RJ-45. **Switch options expanded for AFX 2K**: adds the **Cisco Nexus 9808** chassis switch alongside the existing 9332D-GX2B and 9364D-GX2A fixed switches used on AFX 1K — the 9808 is the more scalable option and its own install guide should be checked before quoting port counts. Same CX6-DX/CX7 mixed copper/optical breakout caveat (KB CHW-3504) applies. Don't reuse AFX 1K port/cable-count numbers for an AFX 2K design — the slot layout and per-port cable type differ.
- [NetApp cluster, management, data, and HA network overview (3rd-party explainer, useful as a primer)](https://www.flackbox.com/netapp-networks-tutorial)
- Two-node systems support **switchless cluster** (direct controller-to-controller cluster-interconnect cabling — no cluster switch) or **switched cluster** (dedicated cluster-network switches); the per-platform guide above documents exact port-to-port cabling for both options and the HA interconnect.
