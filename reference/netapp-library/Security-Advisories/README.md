# Security Advisories — CVEs, NetApp Product Security Advisories, Known Bugs

This category indexes where NetApp vulnerability and known-issue information is published. The running, dated findings log lives in [ADVISORY-LOG.md](ADVISORY-LOG.md), maintained by the daily scheduled refresh (see [OPERATING-PROTOCOL.md](../OPERATING-PROTOCOL.md) for how findings here should shape any recommendation — a customer's current patch level is a safety-relevant fact, not just trivia).

## Primary sources
- [NetApp Security Advisories portal](https://security.netapp.com/advisory/) — the authoritative first stop for CVEs affecting NetApp products; advisories are numbered `NTAP-YYYYMMDD-NNNN` and typically bundle several related CVEs (e.g., a third-party component advisory covering OpenSSL, MySQL, or Ingress NGINX vulnerabilities as shipped inside NetApp products).
- [What is a NetApp Security Advisory? (KB)](https://kb.netapp.com/Support/General_Support/What_are_NetApp_security_advisories) — explains the advisory format (ID, version, last-updated date, status, associated CVEs) and how NetApp triages/publishes them.
- [NetApp Knowledge Base — Security vulnerabilities (formerly "scanner results")](https://kb.netapp.com/Advice_and_Troubleshooting/Miscellaneous/Security_vulnerabilities_(formerly_scanner_results)) — guidance on interpreting third-party vulnerability-scanner findings against NetApp systems specifically.
- [NetApp Trust Center](https://trust.netapp.com/) — compliance/security posture documentation (SOC 2, ISO, etc.), useful for customer due-diligence questions distinct from individual CVE tracking. **New capability found 2026-09-16 (direct-fetch confirmed)**: the SafeBase-hosted portal now also surfaces a "Trust Center Updates" feed carrying dated, named security/incident-transparency notices, not just static compliance documents — two live entries as of this check: (1) a statement on the publicly reported Anthropic "Mythos" agentic-research-model disclosure, in which NetApp states it does not permit use of Mythos internally or in products and, after assessing the associated FreeBSD RPC/GSS vulnerability (published as NetApp advisory `NTAP-20260410-0014`), determined NetApp products are **not presently impacted**; (2) a disclosure that NetApp's Salesloft Drift (third-party sales-lead-management) integration was affected by the broader Salesloft Drift supply-chain incident, potentially exposing standard business contact details (names/business email/phone/region) from NetApp's Salesforce instance — NetApp states the exposure was confined to Salesforce with no evidence of impact to NetApp products or other internal systems, and that affected credentials/tokens were rotated. **Neither item concerns an ONTAP/product CVE requiring customer action** and neither meets this library's notify-the-user bar, but worth knowing this page now carries incident-disclosure content, not just certifications — useful if a customer asks about NetApp's own vendor-risk posture.

## Known bugs / resolved issues (not CVEs, but equally relevant to "don't hit a known landmine")
- Each ONTAP release's "resolved issues" / "known issues" section lives in the version-specific release notes referenced from [ONTAP-Core](../ONTAP-Core/README.md) — check the target/current version's release notes before troubleshooting a symptom that might already be a documented, fixed bug.
- Product-specific release notes elsewhere in this library also carry their own known-issues sections: [SnapCenter](../Data-Protection/README.md#snapcenter), [Astra Trident](../Kubernetes-Containers/README.md#astra-trident-csi-driver) (`trident-rn.html`), [BlueXP/NetApp Console services](../Cloud-BlueXP/README.md).
- [NetApp Interoperability Matrix Tool](https://mysupport.netapp.com/matrix) and [NetApp Support Site case/bug search](https://mysupport.netapp.com/) (support login required) are the authoritative sources for whether a specific bug ID is fixed in a specific version — the public library here can flag that a bug/CVE exists, but confirming fix-version applicability for a specific customer's exact release should go through an authenticated support-site check.

## How findings here should be used (per the Operating Protocol)
- Before recommending an upgrade, workaround, or configuration change in response to a discovered CVE or known bug, confirm the finding actually applies to the customer's in-use product **and version** — advisories frequently scope to a version range, not "all ONTAP".
- Treat any advisory affecting authentication, encryption/key management, or ARP/MAV as high-priority regardless of its published CVSS score, since those subsystems are exactly what the [Security-Hardening](../Security-Hardening/README.md) protections depend on.
- A patch/upgrade recommended as CVE remediation is itself subject to the same [Operating Protocol](../OPERATING-PROTOCOL.md) classification as any other change — an ONTAP upgrade to remediate a CVE is "disruptive but safe" only when the standard NDU pre-conditions are verified first; don't let CVE urgency skip the pre-checks.
- If a discovered CVE has no available patch yet, look for and prioritize NetApp's published mitigation/workaround guidance in the advisory itself before recommending anything improvised.
